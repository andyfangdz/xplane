# Full-scenery follow-up method

The September 13 reduced 2D test established a useful defragmentation workaround. This follow-up keeps the user's scenery arrangement and rendering preferences, temporarily disables VR for the authorized 2D comparisons, and keeps `--gfx_no_defragment` plus the 10 GB disk texture cache throughout. The aircraft, KCDW calm power-off 180, native runtime 0.8.4, loading and guidance parameters are unchanged. TelemFFB-XPP is temporarily isolated to prevent competing control writes; sound and physical joysticks are disabled. Other global plugin directories remain installed, but that does not imply each plugin loaded successfully.

Native after-physics callbacks record consecutive controller step numbers, monotonic wall time and interval duration every frame. The first zero interval is excluded. These are simulator callback intervals, not display-present measurements. The GPU dataref is approximate and is not a GPU execution trace. The primary hitch thresholds are strictly greater than 50 and 100 ms. A secondary local outlier requires an interval greater than both 25 ms and twice its surrounding median, with at least 16 ms excess; the median uses up to 60 samples on each side, excluding the candidate. The per-flight CSVs remain the source of truth.

The full-scene startup exceeded the original 180-second loading allowance. The retained-scenery profile now permits 600 seconds for scene readiness and the first resume, retaining the same position tolerances, airborne entry gates and fuel stability checks. Startup loading is excluded from flight timing. Session A failed before any flight and is retained separately.

The first diagnostic pair used a hidden simulator. The next used a visible simulator; its first flight overlapped UI inspection and is excluded from clean foreground comparisons. Its second flight had no UI interaction. Live hitch-triggered Microprofile dumps were used in both diagnostic pairs. A dump records recent frames, but its request can affect subsequent frames. Request start/end epochs and native trigger intervals are retained. A hitch preceding its triggering request cannot have been caused by that request. Later hitches in the same burst may be affected and are not independent evidence of normal behavior.

The final comparison runs the visible simulator at texture resolution 4, one step below the saved maximum 5, then repeats maximum 5. Each session flies two fresh loads and retains the 10 GB cache, flag and all other rendering preferences. Neither requests live profiler captures or records video. The opening seconds of the first lower-texture flight overlapped a screenshot and focus change; that entire flight remains marked diagnostic. Its second flight has no UI interaction. The later maximum-detail session uses foreground activation during setup before native flight, with no in-flight UI interaction. A planned second resolution-4 pair stopped at a beta aircraft-preview error before either flight, so the planned 4/5/4 sequence was not completed. The evolving disk/OS cache and limited clean sample cannot establish stutter-free behavior across aircraft, weather, scenery or VR, or prove that a small change comes from texture detail.

The VR attempt created an OpenXR instance but returned `XR_ERROR_SYSTEM_INVALID`; runtime VR readbacks remained zero. It was cancelled and restored before any flight. The user explicitly chose to continue in 2D. No result here establishes VR performance.

Landing precision and timing validity are separate. A flight with uninterrupted controller authority can provide valid timing while missing a touchdown-speed tolerance. All landing misses, startup failures and the cancelled VR attempt are retained. Every session must have verified restoration of preferences, SR20 state, scenery contents/links/index, isolated plugin and temporary helpers. Persistent xOrganizer arguments and both 10 GB preferences are checked against their recorded post-change hashes.

Raw logs and Microprofile HTML remain under `D:/X-Plane 12/Output/performance-tests/STUTTER_FOLLOWUP_20260914` and the individual run directories. The report copies derived timing, capture metadata and audit evidence rather than full simulator logs.
